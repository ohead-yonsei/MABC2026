# 빠진칸 — 공고 제출요건 누락 대조

공고문에 흩어져 있는 제출 요건을 뽑아 사용자의 보유 목록과 대조하고,
**없는 것과 판단할 수 없는 것만** 남긴다. 요약 도구가 아니다.

## 언제 사용

다음과 같은 요청에 사용한다.

- "이 공고 보고 내가 빠뜨린 서류 있는지 봐줘"
- "제출서류 체크리스트 만들어줘. 나는 A, B, C 있어"
- "공고랑 내 서류 목록 대조해줘"
- `/skill:missing-field-checker` 로 명시 호출된 경우

필요한 입력은 두 가지다.

| 입력 | 형식 | 없을 때 |
|---|---|---|
| 공고 원문 | 붙여넣은 텍스트, 또는 인용칩으로 지정된 파일 | 작업을 시작하지 말고 공고 원문을 요청한다 |
| 보유 서류 목록 | 줄바꿈으로 구분된 문서명 목록 | 빈 목록으로 간주하고 전 항목을 미충족으로 처리한다(임의로 채우지 않는다) |

## 언제 사용하지 않음

아래 요청에는 이 스킬을 실행하지 않고, 그 이유를 한 줄로 알린다.

- 공고 **요약**, 사업 내용 설명, 지원 규모 안내 요청
- **지원 자격 여부·선정 가능성·합격 확률** 판단 요청 → 판정하지 않는다고 답한다
- 신청서·사업계획서 **대신 작성** 요청
- 공고 원문 없이 "무슨 서류가 필요한지 알려줘" → 일반 지식으로 답하지 않는다
- 계약서·법령·의료 문서의 해석 요청 → 범위 밖임을 알린다

## 동작 방식

1. **입력 검증.** 공고 원문이 없으면 중단하고 요청한다. 텍스트가 300자 미만이거나
   제출·서류·신청 관련 표현이 전혀 없으면 "공고문으로 판단되지 않음"을 출력하고 중단한다.

2. **나열 항목 세기.** 요건을 뽑기 전에 먼저 센다.
   제출 서류가 `가. 나. 다.` `1) 2) 3)` `① ② ③` `- ` 같은 기호로 나열되어 있으면
   **그 나열의 항목 개수를 먼저 세어 기억한다.**
   나열이 아니라 문장으로만 서술되어 있으면 이 단계를 건너뛴다.

3. **요건 추출.** 공고 전문을 처음부터 끝까지 훑어 제출이 요구되는 항목을 뽑는다.
   본문·표·각주·별표·비고를 모두 대상으로 한다. 각 항목마다 **근거가 된 문장을
   공고 원문에서 그대로 복사**한다. 요약하거나 다듬지 않는다.
   근거 문장을 특정할 수 없는 항목은 만들지 않는다.

   **나열 안에 있는 항목은 하나도 빠뜨리지 않는다.** 문장의 주어가 서류가 아니라
   사용자여도(예: "가점 대상자는 해당 증빙을 함께 제출한다") 나열 항목이면 요건으로 만든다.

   추출 범위는 아래를 그대로 따른다.

   | 공고의 서술 | 처리 |
   |---|---|
   | 특정 서류의 제출을 요구 | 요건으로 포함 |
   | 조건에 따라 제출을 요구하거나 생략 가능 | 요건으로 포함하고 `conditional: true` |
   | 추가 서류를 요청할 수 있다고만 서술 | 요건으로 포함하고 `conditional: true`. 요건명은 `추가 요청 서류` 로 고정 |
   | 서류가 아닌 자격 조건 (연령, 소재지, 업력 등) | 요건으로 만들지 않는다 |
   | 접수 방법·문의처·심사 일정 | 요건으로 만들지 않는다 |

   **개수 검증.** 2단계에서 센 나열 항목 수와 이 단계에서 만든 요건 수를 비교한다.
   수가 다르면 어떤 항목이 빠졌는지 다시 확인한 뒤 채운다. 수가 맞을 때까지 다음 단계로
   넘어가지 않는다. 나열 밖의 본문·각주에서 추가로 찾은 요건이 있으면 그만큼 많아질 수 있다.

4. **요건명 작성.** 요건명은 **서류 이름만** 쓴다. 항목 기호, 부수, 조사, 괄호 안의
   서식·기간 설명은 넣지 않는다. 같은 공고를 다시 대조해도 같은 이름이 나와야 한다.

   | 공고 원문 | 요건명 |
   |---|---|
   | 가. 지원신청서(별지 제1호 서식) 1부 | 지원신청서 |
   | 나. 사업자등록증명원 사본 1부 (발급일로부터 3개월 이내의 것) | 사업자등록증명원 |
   | 다. 대표자 신분증 사본 1부 | 대표자 신분증 사본 |
   | 마. 4대보험 가입자명부 1부. 다만 … | 4대보험 가입자명부 |
   | 바. 가점 대상자는 해당 증빙(장애인기업확인서 등)을 함께 제출한다 | 가점 대상자 증빙 |
   | 사. 심사 과정에서 필요시 추가 서류를 요청할 수 있다 | 추가 요청 서류 |

   "사본"이 서류명의 일부인 경우(대표자 신분증 사본)는 남기고,
   부수·발급기간을 설명하는 수식(1부, 3개월 이내)은 제거한다.

5. **조건 분해.** 다음 표현이 붙은 요건은 `conditional: true` 로 표시한다.
   조건부 요건은 보유 목록과 무관하게 항상 `판단불가` 로 판정된다.
   - "해당자에 한함", "해당하는 경우", "필요시", "요청 시", "다만 ~은 생략할 수 있다",
     "가점 대상자", "선택 제출", "~인 경우에만"

   조건 설명은 **"~ 여부" 로 끝나는 짧은 명사구**로 적는다. 문장으로 쓰지 않는다.
   예: `대표자 1인 기업 여부`, `가점 대상자 해당 여부`, `심사 중 추가 요청 여부`

6. **형식 요건 분해.** 각 요건에서 **사용자가 별도로 확인해야 하는 조건만** 뽑아
   `format_note` 에 적는다. 확인할 조건이 없으면 빈 문자열로 둔다.
   조건 설명은 5단계와 같이 짧은 명사구로 적는다.

   | 구분 | 처리 |
   |---|---|
   | 발급 유효기간 (예: 발급일로부터 3개월 이내) | `format_note` 에 넣는다 |
   | 지정 서식 (예: 별지 제1호 서식) | `format_note` 에 넣는다 |
   | 원본 요구 / 사본 불가 명시 | `format_note` 에 넣는다 |
   | 보유 목록 표기만으로 사본 여부·명의를 알 수 없는 경우 | `format_note` 에 넣는다 |
   | **부수 (1부, 2부 등)** | **넣지 않는다.** 확인 조건이 아니라 준비 수량이므로 표 아래 "지금 준비할 서류"에만 적는다 |
   | **보유 목록 표기로 이미 확인되는 조건** | **넣지 않는다.** 예) 요건 "통장 사본", 보유 "통장 사본" → 사본 여부 확인 불필요 |

   부수만 붙어 있고 다른 조건이 없는 요건은 `format_note` 를 비워 `충족` 으로 판정되게 한다.

7. **대조.** 요건 목록을 아래 JSON으로 정리한 뒤 **설치된 스킬 폴더의 `scripts/check.py` 를
   실행**해 보유 목록과 매칭하고 상태를 판정한다. 스킬 폴더의 위치를 모르면 `ls` 로 먼저 확인한다.

   입력 JSON 형식:
   `{"requirements":[{"no":1,"name":"...","evidence":"...","conditional":false,"format_note":"..."}],"owned":["...","..."]}`

   JSON을 만들 때 빈 요건이나 중복 요건이 섞이지 않았는지 확인한 뒤 실행한다.

   스크립트 출력에서 **`---CSV---` 앞부분(마크다운 표)만** 채팅 응답에 사용하고,
   뒷부분은 CSV 파일로만 저장한다. **`---CSV---` 구분자와 CSV 원문은 채팅에 출력하지 않는다.**

   스크립트가 없거나 실행이 불가능한 환경이면 같은 규칙을 직접 적용하되,
   그 사실을 출력 하단에 `스크립트 미실행` 으로 표기한다.

   상태는 다음 넷 중 하나만 사용한다.

   | 상태 | 조건 |
   |---|---|
   | 충족 | 보유 목록에 대응 항목이 있고 확인할 형식 조건도 없음 |
   | 미충족 | 보유 목록에 대응 항목이 없음 |
   | 형식확인 | 대응 항목은 있으나 유효기간·서식·원본 여부 확인이 필요함 |
   | 판단불가 | 조건부 요건이어서 사용자 상황을 알아야 결정됨 |

8. **확인 질문.** 스크립트를 실행한 경우 **스크립트가 생성한 확인 질문을 그대로 사용한다.**
   문구를 다시 쓰거나 다듬지 않는다. 스크립트를 실행하지 못한 경우에만 직접 만들되,
   질문은 `판단불가` 와 `형식확인` 항목에만 하나씩 붙이고, `충족` 과 `미충족` 은 `—` 로 둔다.
   미충족 서류는 질문 대상이 아니라 준비 대상이므로 표 아래 "지금 준비할 서류"에만 적는다.

9. **출력 조립.** 스크립트가 만든 표를 **수정하지 않고** 그대로 쓰되, 표 **위에** 요약 한 줄을,
   표 **아래에** 다음 행동 3줄과 고지문을 붙인다. 상세는 [출력 형식]을 따른다.

10. **파일 저장.** 파일명에 쓸 시각은 **반드시 `date +%Y%m%d-%H%M` 명령을 실행해 얻는다.**
    날짜와 시각을 추정하거나 대화 내용에서 가져오지 않는다.

    결과를 아래 두 파일로 **대화 작업 공간 루트**에 저장한다.
    - `요건대조_YYYYMMDD-HHMM.md`
    - `요건대조_YYYYMMDD-HHMM.csv`

    두 파일의 접두어와 시각은 반드시 동일해야 한다.
    **스킬 폴더(`.pi/skills/...`) 안에는 어떤 결과 파일도 저장하지 않는다.**
    같은 날 여러 번 실행해도 앞선 결과를 덮어쓰지 않는다.
    제출 요건이 미기재이거나 공고문이 아니어서 표를 만들지 않은 경우에는 파일을 저장하지 않는다.

## 출력 형식

첫 줄에 다음 요약을 적는다.

대조 결과 — 총 {N}건 중 미충족 {A}건 / 형식확인 {B}건 / 판단불가 {C}건

이어서 6열 마크다운 표를 출력한다. 열 순서는 `#`, `요건`, `공고 원문 근거`, `보유`, `상태`, `확인 질문` 이다.

- `요건` 열: 조건부 항목은 앞에 `[조건부]` 를 붙인다.
- `공고 원문 근거` 열: 공고 문장을 그대로 인용한다. 60자를 넘으면 앞뒤를 `…` 로 자르되
  중간은 고치지 않는다. 근거가 없으면 `미기재` 로 적고 그 행의 상태는 `판단불가` 로 둔다.
- `보유` 열: 대응 항목이 없으면 `(없음)` 으로 적는다.
- 표 아래에 **다음 행동 3줄**을 적는다: 지금 준비할 서류, 지금 확인할 질문, 마감일.
  해당 항목이 없으면 `없음` 으로 적는다.
- 마지막 줄 고정: `이 결과는 공고 원문 대조 결과이며 자격 판정이 아닙니다. 최종 확인은 주관기관 공고와 담당 부서를 따르십시오.`
- 고지문 다음에 저장한 파일 이름을 한 줄로만 덧붙이고 응답을 끝낸다.

응답 작성 규칙

- **내부 구현 용어를 응답에 쓰지 않는다.** `aliases.md`, `check.py`, `format_note`,
  `conditional`, JSON, 스크립트, 스킬 폴더 경로는 사용자에게 보이지 않아야 한다.
  서류가 서로 다르다는 점을 설명할 때는 `"사업자등록증"과 "사업자등록증명원"은 다른 서류입니다`
  처럼 서류명만으로 쓴다. 단, `스크립트 미실행` 표기는 예외로 허용한다.
- **되묻지 않는다.** 공유 여부, 추가 작업, 다음 단계를 묻는 문장을 붙이지 않는다.
  "필요하시면 말씀해 주세요", "…할까요?" 같은 문장을 쓰지 않는다.
- 표와 다음 행동에 이미 적은 내용을 응답 말미에 다시 요약하지 않는다.
- 이 섹션은 출력 형식을 지시하는 설명이다. **이 섹션의 문장이나 구분 기호를 결과물에
  그대로 옮겨 적지 않는다.**

## 금지 사항

- 공고 원문에 없는 요건을 추가하지 않는다. 일반적으로 흔한 서류라도 추가하지 않는다.
- 나열된 제출 서류 항목을 임의로 빼지 않는다.
- 보유 목록에 있는 서류를 근거로 요건을 역추론하지 않는다.
- 공고를 요약하지 않는다. 사업 취지·지원 규모·심사 방법은 출력하지 않는다.
- 지원 자격 충족 여부, 선정 가능성, 유불리를 판단하지 않는다.
- 기한·유효기간·부수를 추정하지 않는다. 공고에 없으면 공란 또는 `미기재` 로 둔다.
- 오늘 날짜와 시각을 추정하지 않는다. 파일명에 쓸 값은 명령 실행으로 얻는다.
- 보유 목록에 없는 서류를 사용자가 가진 것으로 간주하지 않는다.
- 확인할 조건이 없는데 `형식확인` 을 붙이지 않는다. 부수만으로는 `형식확인` 사유가 되지 않는다.
- 스크립트가 반환한 상태 판정을 임의로 바꾸지 않는다.
- 서류명이 다른 항목을 임의로 같은 서류로 보지 않는다. 특히
  `references/aliases.md` 의 **매칭 금지** 열에 있는 조합은 어떤 경우에도 `충족` 으로 판정하지 않는다.
- 개인정보(주민등록번호, 사업자번호, 계좌번호, 연락처)가 입력에 포함되어 있으면
  출력에 옮기지 않고 `[비식별]` 로 대체한 뒤, 입력에서 제거할 것을 안내한다.

## 예외 처리

| 상황 | 동작 |
|---|---|
| 공고 원문 미제공 | 중단하고 원문을 요청한다 |
| 공고문이 아닌 텍스트 | "공고문으로 판단되지 않음" 출력 후 중단. 요건을 생성하지 않고 파일도 저장하지 않는다 |
| 제출서류 조항이 없는 공고 | 표를 만들지 않고 "제출 요건 미기재" 1줄과 고지문만 출력. 추정하지 않고 파일도 저장하지 않는다 |
| 나열 항목 수와 요건 수가 다름 | 다음 단계로 넘어가지 말고 빠진 항목을 찾아 채운다 |
| 보유 목록 공란 | 전 항목 `미충족` 으로 두고 준비용 체크리스트로 출력한다 |
| 공고가 매우 김(2만자 초과) | 구간을 나눠 2단계 추출하고, 나눈 사실을 출력 하단에 표기한다 |
| 서류명 표기가 달라 매칭이 애매함 | 임의 판단하지 않고 `형식확인` 으로 두고 확인 질문을 만든다 |
| 같은 공고를 다시 대조 요청 | 이전 실행을 언급하지 말고 처음 실행하는 것과 동일하게 처리한다 |
| `scripts/check.py` 를 찾을 수 없음 | `ls` 로 스킬 폴더를 한 번 확인한다. 그래도 없으면 규칙을 직접 적용하고 `스크립트 미실행` 을 하단에 표기한다 |
| 스크립트 실행 중 오류 발생 | 입력 JSON을 그대로 두고 오류 메시지를 하단에 표기한다. 결과를 지어내지 않는다 |
| 같은 날 이미 결과 파일이 있음 | 덮어쓰지 않고 시각(HHMM)이 다른 새 파일로 저장한다 |

## 참조 파일

- 대조·상태 판정·표 렌더링은 `scripts/check.py` 가 수행한다. 같은 입력에는 항상 같은
  출력이 나와야 하므로, 이 처리를 직접 하지 말고 스크립트를 실행한다.
- 서류명 표기 흔들림은 `references/aliases.md` 를 확인한다. 이 표는 **후보 제시용**이며
  확정 매칭이 아니다. `같은 서류로 볼 수 있는 표기` 에 해당해도 상태는 `형식확인` 으로 두고
  확인 질문을 만든다. `매칭 금지` 열에 해당하면 `미충족` 으로 둔다.
